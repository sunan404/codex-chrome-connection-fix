# Codex Chrome Connection Fix

记录一次 Windows 下 Codex 桌面应用与 Chrome 扩展无法连接的完整排查过程：从插件资源初始化失败、代理请求超时，到修复 Xray TUN 自动路由兼容问题，并完成网页读取验证。

**[阅读完整排查记录 →](docs/chrome-codex-connection-debugging.md)**

## 故障表现

- Chrome 扩展已安装、已启用，但 Codex 无法正常读取标签页。
- 初始化时提示内置插件市场的 `marketplace.json` 不存在。
- 后续能够识别扩展实例，但浏览器请求约 21 秒后返回 `nodeRepl.fetch request failed`。
- 显式使用本地代理可以联网，但部分内部请求仍然超时。
- TUN 网卡显示运行中，却没有生成接管外网流量的路由。

## 排查中确认的问题

| 阶段 | 确认的问题 | 处理方式与验证 |
|---|---|---|
| 插件初始化 | Windows 加密资源文件复制失败，插件市场未能完整初始化 | 创建并校验独立资源副本，使用当时版本支持的临时启动覆盖；确认初始化恢复 |
| 网络路径 | 显式代理成功，部分真实浏览器请求仍然超时 | 对比直连与代理结果，继续验证 TUN 的实际接管情况 |
| TUN 配置 | Xray `26.3.27` 不支持生成配置中的自动路由等字段 | 更新到支持相关字段的官方预发布版 `26.10.10`，开启 TUN 与自动路由 |
| 最终验收 | 浏览器连接恢复后，原标签页仍曾控制超时 | 手动刷新原标签页，随后成功读取页面内容 |

## 修复后的结果

- TUN 接口获得配置中的地址，生成默认路由。
- Codex 能够枚举 Chrome 中已有的标签页。
- Codex 能够接管原标签页并读取可见网页内容。

以上结论来自本次环境的实际验证。扩展已安装、网卡显示 `Up`、独立 Node 请求成功，都不能单独代替完整连接验证。
